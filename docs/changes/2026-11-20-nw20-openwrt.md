# 2026-11-20: NW-20 puts firewall rules on the OpenWRT router

- **NW-20** (1.2.0): new brand `openwrt`. The rules go in their own nftables table `inet bt_fw` (forward hook, before fw4's), kept in `/etc/bt_fw.nft` and loaded by fw4 at every reload and boot through a uci `include`; root, no sudo. The router is asked which device is wan, and that one is offered first as OUTSIDE.
- **Port forwards kept:** the router's enabled port forwards (uci `redirect`, from wan, DNAT) are listed, and "keep these N port forward(s) open?" is asked (default yes; `--no-forwards` says no). Each kept one is allowed to its inside address and port, which is what the forward chain sees after the forward. The login ports and outside addresses from the last change still apply.
- **Undo:** the table deleted, the uci include removed, the file deleted (`undo/router.sh`, or `--remove --apply`). As for every brand, every scored service is tried before and after, and everything is put back if one stops answering, then you confirm against the scoreboard.
- **Questions:** which firewall and its password are now asked when no flag says (the library questions), like the other network scripts.
- Tested: nw20 under dash, bash, ksh93, mksh, yash (the background-stop check skipped, as before) and busybox sh; gawk, mawk and busybox awk; the built copy. OpenWRT with a stand-in router (wan device, an enabled and a disabled port forward, dry run, apply, undo record, `--no-forwards`). Not yet on a real OpenWRT router.
